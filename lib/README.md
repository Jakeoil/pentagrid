# `lib/` — this project's public entry points

Small hand-written files, one per subject, that name what this repo promises
and re-export it. Import them by relative path from a checkout beside this
one, or by URL from the site:

```js
// local development, from a sibling project
import { createGammaSet } from "../pentagrid/lib/gamma.js";

// or published
import { mountFloatingReticulum }
    from "https://jakeoil.github.io/pentagrid/lib/reticulum.js";
```

The plan behind all of this — what is exposed, what is not, and why it lives
here rather than in a repository of its own — is `../LIBRARY.md`.

## Three things to know before you rely on it

**Names in `lib/` are a promise; paths under `dist/` are not.** The internal
layout moves, and has four times in two months. `tools/surface.test.mjs` holds
a golden list of every name each entry exports, so the surface cannot change
without someone deciding to let it. Importing `dist/…` directly works and is
what the whole-canvas examples in `../MODULES.md` do — it is simply not
promised.

**`dist/` is built, not committed.** `.gitignore` lists it and
`.github/workflows/deploy.yml` runs `npm run build` on every push, so the
modules exist on the website and in a working tree and nowhere else. A fresh
clone needs one `npm run build` before `lib/` resolves. This is also why a git
or jsDelivr dependency on this repo would not work — it would fetch a tree with
no `dist/` in it. See `../LIBRARY.md` §6.

**The browser needs one HTTP root above both projects** for the sibling import
to resolve: a page served from its own project cannot reach `../pentagrid/`,
because the server sanitizes `..` away. Serving the parent directory of both
checkouts is the no-code answer, and then the import path is the same string
locally and published.

## Types

A `.d.ts` sits beside each entry, so a TypeScript consumer gets the real
declarations from the same path it imports the code from, with no `paths`
mapping. The declarations themselves are generated into `../dist/` by the
build, alongside the JavaScript.

## Stylesheets

`lib/css/` holds the instruments' look, carved out of this project's own
`site.css`, which now imports these files rather than keeping a copy — so what
you link cannot drift from what the site shows.

| file | for |
|---|---|
| `lib/css/reticulum.css` | the reticulum, its Σ strip, the three exponent boxes |
| `lib/css/panel.css` | the floating panel |
| `lib/css/dials.css` | the γ bank of linked sliders |
| `lib/css/loupe.css` | the magnifier |

```html
<link rel="stylesheet" href="../pentagrid/lib/css/reticulum.css">
<link rel="stylesheet" href="../pentagrid/lib/css/panel.css">
```

Structure is inline — each piece positions its own parts, per `../MODULES.md` —
so an unstyled instrument works and looks like unstyled HTML.
